# Runda 22 (v0.3): sterowanie zadaniami z web UI

Dziś `app/web/` tylko czyta JSONL. Cel: z przeglądarki wysłać zadanie i widzieć
jego przebieg bez terminala — bez zmiany rdzenia pętli i bez nowych zależności
Rust.

## Architektura (jedna decyzja, reszta wynika)

Nowy, mały serwer HTTP obok statycznego UI, w **Pythonie** w `app/web/serve.py`
(standard biblioteki: `http.server`, `subprocess`, `json`). Powody: rdzeń w Rust
zostaje bez zależności HTTP (ADR/README), a serwer to warstwa UI, nie agent.

Serwer:
- serwuje pliki `app/web/` (jak `python3 -m http.server`) **oraz** `.agent/sessions/`
  z workspace,
- `GET /api/sessions` → lista jak dziś,
- `GET /api/sessions/<id>` → pełny JSONL (albo `?since=<offset>`),
- `POST /api/run` → uruchamia `ardntai run -w <workspace> "<tekst>"` jako proces
  potomny, zwraca `{"session": "<id>"}` zanim skończy,
- `POST /api/run?resume=1` → `ardntai run --resume "<tekst>"`,
- jedno zadanie naraz (`409` przy drugim), zabicie procesu przy `Ctrl+C` serwera.

Bezpieczeństwo: bind tylko `127.0.0.1`, brak CORS, `POST` wymaga
`Content-Type: application/json` i pola `task`; ścieżki sesji walidowane jak
dziś (whitelist z katalogu, żadnych `..`).

## UI

- Pole „nowe zadanie” + przycisk `Uruchom` (Enter); podczas biegu `Zatrzymaj`.
- Status biegu: `idle | running | done | failed` + jego session id.
- Po starcie widok przełącza się na nową sesję i **tailuje** ją co 1 s
  (jak dziś, 2 s → 1 s w trakcie biegu).
- Gate'y (`kind: gate`) widoczne (już są).
- Błąd startu (brak binarki, 409, zły JSON) → komunikat w pasku, bez crasha.

## Kryteria PASS (odbieram w Orca browser)

1. `cargo test` → 242 + 22, `demo` → 39/39 (rdzeń nietknięty).
2. `python3 app/web/serve.py --workspace /tmp/ws-web` startuje na 127.0.0.1:8766;
   `GET /api/sessions` → `[]`, UI się otwiera.
3. `POST /api/run` z `{"task":"write a.txt :: z-web"}` → 200 z session id;
   po ≤ 5 s w UI widać `task`, `thought`, `tool_call`, `tool_result`, `summary`
   i plik `a.txt` powstaje w workspace.
4. Drugi `POST` w trakcie biegu → 409 z czytelnym komunikatem; UI to pokazuje.
5. `POST` z `{"task":"../../etc/passwd"}` → zadanie idzie jako **treść**, nie
   ścieżka; serwer nie czyta plików spoza workspace.
6. `grep -c "crate" app/src/*.rs` bez zmian zależności: w `app/Cargo.toml`
   zero nowych wpisów.
7. Zrzut `app/shots/v0.3-web-run.png` (widok w trakcie biegu).
